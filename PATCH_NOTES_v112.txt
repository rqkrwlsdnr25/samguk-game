삼국쟁패 v112 — 내정 / 모병 / 건설 코드 감사 및 안정화 패치
기준: v111 game.js

[실제 확인된 원인]
1) 미선택 상태 오인
   - selected가 null일 때 Number(selected)가 0이 되어 0번 영토가 선택된 것처럼 처리될 수 있었습니다.
   - 내정 컨텍스트, v110 렌더 fallback, 침략 source 검사에서 null/undefined/''를 숫자 변환 전에 차단했습니다.

2) 유효하지 않은 actionMode 사용
   - v111 내정 이벤트 브리지가 도시/수도 증축 클릭 시 actionMode='cityUpgrade' / 'capitalUpgrade'를 설정했습니다.
   - 실제 render()가 인식하는 값은 'city' / 'capital'이므로 UI 상태가 끊기거나 패널이 사라질 수 있었습니다.
   - 렌더 계약과 동일한 'city' / 'capital'로 수정했습니다.

3) 전투/침략 잔여 상태가 내정에 섞이는 문제
   - 내정 진입 시 lightweight invasion의 active/launching/supporting만 지워지고 targets/sourceId/targetId 및 CSS 상태가 남을 수 있었습니다.
   - 내정 진입 시 침략 클래스, targets, sourceId, targetId까지 완전히 초기화합니다.

4) 잘못된 탭/건물 key의 묵시적 fallback
   - 알 수 없는 domestic tab이 자동으로 모병 탭으로 바뀌고, 잘못된 building key가 하위 함수까지 전달될 수 있었습니다.
   - recruit/build 탭 whitelist와 BUILDINGS key 검증을 추가했습니다.

5) 모병 성공 후 최종 UI 확정 렌더 미보장
   - 하위 모병 함수의 render가 이전 안전 래퍼에서 격리되면 실제 자원/병력 갱신 뒤 화면이 이전 값으로 남을 수 있었습니다.
   - 성공 mutation 확인 후 safeRender를 한 번 더 실행합니다.

6) 프로그램 호출 경로의 선택 검증 불균일
   - UI 클릭은 Guard를 거치지만 외부/구형 코드가 recruit(), recruitCavalry(), recruitSpecial()을 직접 호출하는 경로는 검증 계층이 달랐습니다.
   - 세 모병 엔트리 모두 동일한 selectedContext 검증을 먼저 통과하도록 통일했습니다.

7) stale domestic 상태 렌더
   - 영토 소유권 변경/선택 해제 후 actionMode='domestic'이 남으면 패널 렌더가 잘못된 영토를 참조할 수 있었습니다.
   - safeRender 직전에 선택/소유권을 재검증하고 invalid domestic 상태는 inspect로 복구합니다.

[보존한 규칙]
- 기존 v111 전투/AI/경제/STEPPE/장수/왕권 시스템은 재작성하지 않았습니다.
